# Deploy "Keep" to Vercel (From Scratch)

## Goal
Deploy the Next.js 16 app in this repo to Vercel as a full production deploy: create the Vercel project, connect the GitHub repo (`eloooong/keep`, branch `master`), configure all environment variables, enable the daily expiry-email cron job, and validate the production build and routes.

## Current State
- **Runtime**: Next.js 16.3.3 (Turbopack), React 19, App Router. Deployed on the Node.js runtime (default).
- **Git**: `origin` = `https://github.com/eloooong/keep.git`, only branch `master`. No `.vercel/` local config yet → fresh import.
- **Auth**: Supabase SSR via `src/utils/supabase/*`. Middleware lives in `src/proxy.ts` (Next 16 file-based `proxy`, auto-detected — no config changes needed).
- **Cron**: `vercel.json` defines one cron: `GET /api/cron` at `"0 8 * * *"` (08:00 daily). Handler `src/app/api/cron/route.ts` guards with `Authorization: Bearer ${CRON_SECRET}` and sends expiry reminders via Resend.
- **Env vars referenced in source**:
  - `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY` (client/server/proxy)
  - `SUPABASE_SERVICE_ROLE_KEY` (service client + cron)
  - `CRON_SECRET` (cron auth)
  - `RESEND_API_KEY` (cron emails)
  - `EMAIL_FROM` (optional; defaults to `noreply@apikeysaver.app`)
  - `NEXT_PUBLIC_VERCEL_URL` — **auto-set by Vercel**, do not configure manually.
- **Secrets**: `.env*` is gitignored; `.env.local` holds local values. Nothing should be committed.

## Scope
- Create Vercel project + connect Git repo, configure env vars, verify cron, validate production.
- **Out of scope**: Supabase schema/migrations (`supabase/schema.sql` — managed in Supabase dashboard, not Vercel), custom domains/SSL, auth providers config beyond what env vars cover, and the Activity-page/dashboard UI work.

## Design Decisions
1. **Import from GitHub** (not `vercel deploy` CLI). Recommended so future pushes to `master` auto-deploy preview + production and the cron is wired to the repo.
2. **Framework preset**: Vercel auto-detects Next.js. Leave build command as the default (`next build` for Next 16, or as detected). Output directory is unset (default).
3. **Env scope**: Enter missing secrets in the Production + Preview + Development environments (or "All"). Mark the three `NEXT_PUBLIC_*` values as visible (they must be inlined client-side).
4. **Cron**: Vercel Cron requires a **Hobby** tier or above; free tier does not support crons. The cron invokes `/api/cron` and Vercel automatically sends `Authorization: Bearer <CRON_SECRET>` from the `CRON_SECRET` env var — the existing guard matches this pattern, so no code change needed.
5. **Package manager**: npm (repo has `package-lock.json`); Vercel will use it automatically.

## Implementation Task List
1. **Pre-flight checks (local)**
   - Confirm `npm run build` passes clean (env from `.env.local`). This has already been verified in recent work, but rerun once.
   - Confirm `npm run lint` passes (0 errors / 0 warnings).
   - Confirm `vercel.json` cron path/schedule is as intended; confirm `src/app/api/cron/route.ts` compiles under the build (it is included by Next as a route).
2. **Create the Vercel project**
   - Open https://vercel.com/new and import the `eloooong/keep` GitHub repo.
   - Framework preset: Next.js (verify detected framework + build command).
   - Root Directory: `/` (repo root).
   - Region: choose one close to users/database (e.g. `iad1` US East). Optional but recommended for consistency with Supabase region.
   - Project name: `keep` (or as preferred).
3. **Configure environment variables** (enter in Vercel project → Settings → Environment Variables, environment = Production/Preview/Development):
   - `NEXT_PUBLIC_SUPABASE_URL` (visible)
   - `NEXT_PUBLIC_SUPABASE_ANON_KEY` (visible)
   - `SUPABASE_SERVICE_ROLE_KEY` (secret — confirmed value from Supabase Service Role key)
   - `CRON_SECRET` (secret — any strong random string; must match what the cron uses)
   - `RESEND_API_KEY` (secret)
   - `EMAIL_FROM` (secret, optional — valid "Sender" address verified in Resend)
   - Do NOT set `NEXT_PUBLIC_VERCEL_URL` (auto-provided).
4. **Deploy**
   - Trigger the first production deploy (Vercel will deploy on import; or click "Deploy").
   - Verify build logs complete with the route table (`/`, `/login`, `/signup`, `/activity`, `/api/cron`, `/auth/callback`).
5. **Enable the cron**
   - If the account is on Hobby tier or above, verify the cron appears under Vercel → Settings → Cron Jobs with the `0 8 * * *` schedule.
   - Confirm `CRON_SECRET` is set so the cron's `Authorization` header matches the handler guard.
   - Note: on Hobby the cron runs once daily at the configured time. On the free tier, crons are not supported → recommend a Hobby upgrade.
6. **Post-deploy validation**
   - Visit the production URL: `/` redirects to `/login` when unauthenticated; `/login` and `/signup` render.
   - Authenticate and confirm the dashboard loads (keys list, header, logout icon).
   - Hit `/api/cron` manually with `Authorization: Bearer <CRON_SECRET>` (e.g. via curl) → expect `200` with `{"sent":0}` or an email count; without the header → `401`.
   - Confirm the "Go to Dashboard" link in generated emails points to `https://${NEXT_PUBLIC_VERCEL_URL}`.
   - Smoke-test a new deploy by pushing a trivial commit to `master` and confirming auto-deploy + cron persists.

## Validation
- `npm run lint` → 0 errors / 0 warnings.
- `npm run build` → green; route table includes all app routes.
- Production site: auth flow works against Supabase; dashboard functional.
- Cron endpoint: `401` without bearer, `200` with bearer, email deliverable via Resend.
- Git push to `master` triggers an automatic production redeploy.

## Risks / Notes
- **Cron availability**: Free-tier Vercel projects cannot run crons; a paid (Hobby+) plan is required. If the user stays on Free, the cron silently won't fire — flag this before/after deploy.
- **Service role key**: `SUPABASE_SERVICE_ROLE_KEY` bypasses RLS — keep it only in server env (it is already not `NEXT_PUBLIC_*`, so it won't be exposed client-side).
- **Cron idempotency / double-run**: `email_reminders` dedupes by `key_id`, so a single unexpected re-run won't send duplicates.
- **Region mismatch**: If Vercel region ≠ Supabase region, add some latency; not a blocker.
- **Custom domain**: out of scope; only the default `*.vercel.app` URL is configured here.
- **`proxy.ts` on Vercel**: Next 16 treats `src/proxy.ts` as the framework proxy; it deploys automatically with the default matcher — no `vercel.json` rewrite needed.

## Open Questions (none blocking; optional)
