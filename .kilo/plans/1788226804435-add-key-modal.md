# Convert "Add a key" to a modal + keep key table focused

## Goal

Replace the always-visible inline "Add a key" section on the dashboard (`/`) with a compact **"Add key"** button in the page header that opens the existing `NewKeyForm` in a **modal overlay**. The dashboard body becomes a focused key table (plus the existing expiry banner and toolbar). On a successful create the modal closes and the key table refreshes to show the new key immediately.

## Current state (relevant)

- `src/app/page.tsx:71-76` renders `<section>` "Add a key" containing `<NewKeyForm />` inline between the expiry banner and the "Your keys" list.
- `src/components/keys/NewKeyForm.tsx` is a client component; its form action wraps `await createKey(formData)` then calls `router.refresh()` (added in the preceding fix) and `onSubmit?.()`. The `onSubmit` prop exists but is currently unused by `page.tsx`.
- `NewKeyForm` uses `AnimatedContent` (mount/fade-slide) and `Magnet` (hover tilt) from `src/components/react-bits/`.
- No modal/dialog component exists yet in the codebase.
- `src/app/page.tsx` is a server component (async, fetches keys). `NewKeyForm` is the client boundary.
- Tooling: Next 16.3.3 (React 19), Tailwind v4, `react-hooks/*` rules enforced (setState only in handlers/timeouts/rAF — never synchronously in an effect body).

## Design

### Trigger button placement (REVISED — not in header)
- The **Add key** button does **not** live in the page header. Instead it is placed in the **"Your keys" section heading row** (`src/app/page.tsx:72-75`).
- Convert the `h2` block into a flex heading row: title + `KeyCount` on the left, `<AddKeyButton />` right-aligned (`justify-between items-center`). This keeps the primary action aligned with the collection it acts on and is visible in both the populated and empty states.
- Client/server note: `AddKeyButton` is already a client component; it mounts fine inside the server-rendered `page.tsx`. It carries no server props.

### New modal component
Create `src/components/keys/KeyFormModal.tsx` (`"use client"`), an accessible modal wrapper:

- Props: `open: boolean`, `onClose: () => void`, `children: ReactNode` (renders `<NewKeyForm ... />`).
- Renders a fixed full-screen overlay (backdrop) with a centered panel when `open`. Use a plain portal (`createPortal`) to `document.body` to avoid stacking/transform issues with `AnimatedContent`/`Magnet`.
- Accessibility: `role="dialog"`, `aria-modal="true"`, `aria-labelledby` on a title inside the panel; Escape key closes; click on backdrop closes; focus moves into the panel on open and a close (`×`) button is present.
- Add closing on Escape/backdrop and keep the panel STOP-closed on save via `onClose` called by the parent.

### Wire into dashboard (`src/app/page.tsx`)
- Remove the inline "Add a key" `<section>` (lines ~71-76).
- Add a client boundary for the trigger button + modal state. Since `page.tsx` is a server component, the button and modal live in a small client component: `src/components/keys/AddKeyButton.tsx` (`"use client"`, owns `const [open, setOpen] = useState(false)`).
  - Renders an "Add key" button and, when `open`, a `<KeyFormModal>` whose children are `<NewKeyForm onSubmit={() => setOpen(false)} />`.
- Convert the "Your keys" `h2` block into a flex heading row (`justify-between items-center`): title + `KeyCount` on the left, `<AddKeyButton />` right-aligned. Remove `<AddKeyButton />` from the header navigation group.
- Keep `NewKeyForm`'s own `router.refresh()` inside its action so the table re-fetches on create; the parent `onSubmit` now additionally closes the modal.

### Interactions / data flow
1. User clicks **Add key** in the "Your keys" heading → modal opens, form visible.
2. Submits → `createKey(formData)` runs (server action + `revalidatePath("/")`), then `router.refresh()` re-fetches the mounted client tree's server data, then `onSubmit?.()` closes the modal.
3. Table (now the prominent body) reveals the new key via the existing `AnimatedList` in `KeysList`.
4. User can close via `×`, Escape, or backdrop without saving.

## Edge cases / considerations
- **Portal + focus**: use `createPortal` to `document.body`. Move focus onto the panel (or a visually-hidden heading) on open and restore focus to the trigger on close. Keep the overlay non-scrollable while open (`overflow-hidden` on body while open) to avoid background scrolling.
- **`AnimatedContent`/`Magnet` inside modal**: they already animate on mount; ensure the modal panel doesn't clip them (no `overflow-hidden` on the panel wrapper).
- **StrictMode**: the modal mount/unmount runs twice in dev; ensure the portal/focus effect cleanup is correct (no stale timer refs left).
- **Empty-state**: when there are no keys, the "No API keys yet" empty state remains — the "Your keys" heading Add key button stays available so users can still create a first key.
- **Server/client boundary**: keep `page.tsx` a server component; only the new client components hold state.
